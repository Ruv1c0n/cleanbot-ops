🤖 Файл **protocol-rest.md** описывает REST‑API симулятора роботов.

**База**: `http://<host>:8080`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/robots` | список всех роботов (id, name, state, battery, error) |
| GET | `/robots/{id}` | данные одного робота |
| POST | `/robots/{id}/commands` | отправить команду роботу (`START`, `PAUSE`, `RESUME`, `ABORT`, `RETURN_HOME`, `RESET`) |
| GET | `/robots/{id}/schedules` | текущее расписание |
| PUT | `/robots/{id}/schedules` | заменить расписание целиком |
| GET | `/robots/{id}/sessions?from&to` | история сессий по датам (ISO‑8601) |
| GET | `/robots/{id}/logs` | журнал событий (новые сверху) |
| GET/PUT | `/robots/{id}/settings` | настройки робота |

**Ответы**:
- При успехе: `{"accepted": true, …}`
- При неудаче: `{"accepted": false, "reason": "ILLEGAL_STATE"}` или `"UNKNOWN_COMMAND"`.

Таким образом, файл фиксирует все эндпоинты, команды и формат ответов для взаимодействия с роботом.

🤖 **Коротко о протоколе телеметрии (WebSocket):**

- Подключение: `GET ws://<host>:8080/telemetry` – сервер отправляет раз в ~1 секунд JSON‑массив с телеметрией всех роботов.
- Формат элемента массива:

```json
{
  "robotId": "cleanbot-01",
  "timestamp": "2026-09-05T14:32:11Z",
  "state": "CLEANING",
  "battery": 63,
  "progress": 0.42,
  "position": { "x": 12, "y": 4 },
  "error": null
}
```

- Состояния (`state`): `IDLE | CLEANING | PAUSED | RETURNING | CHARGING | ERROR`.
- Ошибки (`error`): `STUCK`, `BRUSH_JAMMED`, `TANK_FULL`, `SENSOR_FAULT`, `LOW_BATTERY`.
- Симуляция:
  - `CLEANING`: заряд –1 %/тик, прогресс +2 %/тик.
  - При заряд <= 15 % → `RETURNING`; при прогрессе 100 % → `RETURNING`.
  - `CHARGING`: заряд +3 %/тик до 100 %.
