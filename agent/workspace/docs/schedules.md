# Расписания уборки

## Структура записи

Каждая запись расписания (`Schedule`) содержит:

- `id` — идентификатор записи;
- `robotId` — идентификатор робота;
- `dayOfWeek` — день недели, 1..7, понедельник = 1 (ISO);
- `time` — время запуска в формате `HH:mm` (00:00–23:59);
- `mode` — режим уборки: `dry_sweep` (сухая подметание) или `wet_mopping`
  (влажная мойка).

Пример записи:

```json
{ "id": "s1", "robotId": "cleanbot-01", "dayOfWeek": 3,
  "time": "09:30", "mode": "dry_sweep" }
```

## Замена расписания

`PUT /robots/{id}/schedules` заменяет список записей **целиком** —
частичное обновление не предусмотрено. Тело запроса:
`{ "entries": [ ... ] }`. При ошибке валидации ответ — 400 с текстом
ошибки (plain text) и указанием номера записи.

## Валидация

- `dayOfWeek` в диапазоне 1..7;
- `time` соответствует регулярному выражению `HH:mm` (00:00–23:59);
- `mode` — один из `dry_sweep`, `wet_mopping`;
- `robotId` каждой записи совпадает с идентификатором робота в пути
  запроса (иначе запись запускала бы чужого робота).

## Автозапуск по расписанию

Раз в 15 секунд сервер сверяет день недели и время (локальная таймзона
сервера) с расписаниями. Совпавшая запись запускает уборку (режим берётся
из записи), если робот находится в состоянии `IDLE`. Если робот занят
(убирает, заряжается, в ошибке), запись не выполняется — в журнал событий
робота попадает пометка о пропуске.

## Дедупликация

Одинаковые записи (тот же день, время и режим для одного робота) не
должны дублироваться: дедупликация расписания идёт по дате и времени
запуска, чтобы в одно время не стартовали две уборки одного робота.
