## 📖 О проекте

Идея выросла из реальной эксплуатации промышленных клининговых роботов: оператору нужно единое окно, в котором видно состояние каждой машины в парке и откуда можно отдать команду или поправить расписание — не подходя к роботу и не открывая панель на месте.

**cleanbot-ops** — MVP такой консоли: Android-приложение с телеметрией в реальном времени, удалённым управлением, расписаниями, историей сессий и инженерным меню.

Вместо реального железа в репозиторий входит **симулятор — цифровой двойник робота**: Ktor-сервер, моделирующий поведение машины конечным автоматом и раздающий телеметрию по WebSocket. Разработка и тестирование клиентских приложений на цифровом двойнике — стандартная индустриальная практика; интерфейс обмена спроектирован так, чтобы вместо симулятора можно было подставить реальный источник данных.

> Проект выполнен в рамках курса **«Современные технологии в программировании»**.

### Поведение робота — конечный автомат

Каждый робот в симуляторе — детерминированная машина состояний. Команда, недопустимая в текущем состоянии, отклоняется с кодом `ILLEGAL_STATE` — как и на реальном устройстве.

| Текущее состояние | Событие | Следующее состояние |
|---|---|---|
| `IDLE` | `start` | `CLEANING` |
| `IDLE` | `return_home` | `RETURNING` | REST-команда |
| `CLEANING` | `pause` | `PAUSED` |
| `PAUSED` | `resume` | `CLEANING` |
| `CLEANING` / `PAUSED` | `abort` / `return_home` | `RETURNING` |
| `RETURNING` | `docked` | `CHARGING` |
| `CHARGING` | `battery_full` | `IDLE` |
| любое, кроме `ERROR` | `fault` | `ERROR` |
| `ERROR` | `reset` | `IDLE` |

## 🔌 Протокол обмена

Полная спецификация — [`docs/protocol.md`](docs/protocol.md).

**Телеметрия** (WebSocket, пуш ~раз в секунду, по всем роботам):

```json
{
  "robotId": "cleanbot-02",
  "timestamp": "2026-09-05T14:32:11Z",
  "state": "CLEANING",
  "battery": 63,
  "progress": 0.42,
  "position": { "x": 12, "y": 4 },
  "error": null
}
```

**Команда** (REST, `POST /robots/{id}/commands`):

```json
{ "command": "PAUSE", "requestId": "b1c2d3e4" }
```

Ответ: `{ "accepted": true, "requestId": "b1c2d3e4" }` либо `{ "accepted": false, "reason": "ILLEGAL_STATE" }`.

**Коды ошибок робота:** `STUCK`, `BRUSH_JAMMED`, `TANK_FULL`, `SENSOR_FAULT`, `LOW_BATTERY`.

## 🚀 Запуск

**Требования:** JDK 17+, актуальная Android Studio, Android SDK.

```bash
# 1) Симулятор (поднимается на порту 8080)
./gradlew :simulator:run

# 2) Приложение — открыть корень репозитория в Android Studio → Run
#    либо из консоли:
./gradlew :app:installDebug
```

**Адрес симулятора** задаётся в инженерном меню приложения:

| Где запускается приложение | Адрес симулятора |
|---|---|
| Android-эмулятор | `ws://10.0.2.2:8080` (`10.0.2.2` — loopback хост-машины) |
| Физическое устройство | `ws://<IP-компьютера-в-той-же-сети>:8080` |

## 🤖 Лабораторная 3: агент с контекстом и памятью

CLI-агент (`agent/agent.py`) поверх OpenAI-совместимого API: инструменты (`list_files`,
`read_file`, `write_file`, `search_docs`, `add_task`, `list_tasks`), персистентные сессии,
бюджет контекста с усечением (trim) или суммаризацией старого хвоста, поиск по документации
проекта и fallback на онлайн-модель, если локальная Ollama недоступна.

**Запуск с нуля:**

```bash
cd agent
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # Linux/macOS: .venv/bin/pip
cp .env.example .env                            # заполнить ключи

# локальная модель через Ollama (по умолчанию):
ollama serve                                    # в отдельном терминале
ollama pull gpt-oss:latest

PYTHONIOENCODING=utf-8 .venv/Scripts/python agent.py --session mysession
```

**Флаги:**

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--session <id>` | история диалога хранится в `agent/sessions/<id>.json` (переживает перезапуск) | `default` |
| `--strategy trim\|summarize` | что делать со старым хвостом при превышении бюджета: удалять целиком или сжимать в «память диалога» | `trim` |
| `--budget N` | бюджет контекста в «условных токенах» (`len/4` по сообщениям + tools) | `6000` |

**Структура:**

- `agent/sessions/` — файлы сессий `<id>.json` (в git не попадают);
- `agent/workspace/` — песочница агента: `docs/` — корпус для `search_docs`, `tasks.json` — список задач;
- `agent/LAB3.md` — отчёт по лабораторной (шаги, логи прогонов, наблюдения);
- `agent/log_*.txt` — вшитые в отчёт логи сквозных прогонов;
- переменные окружения: `BASE_URL`, `API_KEY`, `MODEL` — основная модель; `FALLBACK_BASE_URL`,
  `FALLBACK_API_KEY`, `FALLBACK_MODEL` — запасная онлайн-модель (см. `.env.example`).

Выход из агента — `exit`. Тесты контекстной логики: `cd agent && .venv/Scripts/python -m pytest test_agent.py`.

## ⚠️ Известные ограничения

- Симулятор хранит данные **в памяти**: перезапуск сбрасывает расписания и историю (она заново генерируется за последний месяц).
- Один пользователь, без авторизации и ролей — осознанное ограничение MVP.
- Вся телеметрия синтетическая: это цифровой двойник, а не реальные данные.
- Расписание не запускает уборку автоматически
- Адрес сервера не сохраняется
